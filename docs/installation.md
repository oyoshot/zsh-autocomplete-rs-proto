# Installation

Install the executable and Zsh adapter from the same revision. Put
`zsh-autocomplete-rs` on `PATH`, then source the adapter after `compinit` in your
Zsh configuration:

```zsh
source /path/to/zsh-autocomplete-rs.plugin.zsh
```

The adapter reads its four `_zacrs_*.zsh` helpers from the same directory. Keep
all five files together. The `init zsh` command has been removed; replace
`source <(zsh-autocomplete-rs init zsh)` or its `eval` equivalent with the source
line above. The executable no longer embeds or generates shell code.

## Nix

This repository supplies `package.nix`. It uses the caller's nixpkgs and Zsh;
there is no separate nixpkgs pin or flake. For a source input named `zacrs-src`:

```nix
zacrs = pkgs.callPackage (inputs.zacrs-src + "/package.nix") { };
```

`shellInstallDir` selects the adapter directory relative to `$out`. It defaults
to `share/zsh-autocomplete-rs`; for example:

```nix
zacrs = pkgs.callPackage (inputs.zacrs-src + "/package.nix") {
  shellInstallDir = "share/zsh/plugins/zacrs";
};
```

When overriding this directory, use the same path in your `source` line or
plugin-directory link. Sources and compiled files are installed and checked in
the selected directory together.

Add `zacrs` to your packages. With the default directory, the output contains:

```text
bin/zsh-autocomplete-rs
share/zsh-autocomplete-rs/zsh-autocomplete-rs.plugin.zsh
share/zsh-autocomplete-rs/_zacrs_util.zsh
share/zsh-autocomplete-rs/_zacrs_gather.zsh
share/zsh-autocomplete-rs/_zacrs_compsys.zsh
share/zsh-autocomplete-rs/_zacrs_protocol.zsh
```

Each shell file also has an adjacent `.zwc`. In Zsh configuration generated by
Nix, use the package reference to select the matching adapter:

```nix
''
  source ${zacrs}/share/zsh-autocomplete-rs/zsh-autocomplete-rs.plugin.zsh
''
```

The package compiles the files at build time and checks their syntax and compiled
format. Full native tests require PTYs and Unix sockets and run outside the Nix
build. Building the package does not start or stop a daemon. Your activation
must implement the [daemon update lifecycle](configuration.md#daemon-updates).

## Other installation methods

`cargo install --path .` installs only the executable. Source the plugin from
the matching checkout, or copy `shell/*.zsh` together into an installation
directory such as `$prefix/share/zsh-autocomplete-rs`. Other package managers can
install the same layout.

To avoid parsing the shell files at each startup, compile them once during
installation with the Zsh that will read them:

```zsh
zsh -dfc '
    for file in "$1"/*.zsh; do
        zcompile -U "$file" || exit
    done
' _ /path/to/zsh-autocomplete-rs
```

`-U` prevents aliases from being expanded while compiling. Continue sourcing the
`.zsh` entry point: Zsh selects usable adjacent `.zwc` files when they are at
least as new as their sources. Keep the sources as a fallback. Rebuild the
compiled files when zacrs or the packaged Zsh changes; do not distribute one
host's bytecode as a universal artifact. No startup cache generation, version
checks, `fpath` changes, or additional hooks are needed for this loading method.

An existing shell keeps its loaded code until you source the installed entry
point again or start a new shell. Reloading preserves explicit completion
selections. For incompatible shell/daemon protocol updates, start a new shell.
Settings still hot-reload independently of these files.
